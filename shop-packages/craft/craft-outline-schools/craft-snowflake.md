# Snowflake Method (Randy Ingermanson)

Fractal design: start tiny, expand until the novel is designed.

## Light

Job: organize a novel’s design before (or after) drafting so large-scale holes surface early.

Contract: living design docs — revise earlier steps when characters teach you; not a frozen outline.

Must-not-break:
- One-sentence summary first (≤~15 words; no character names; big picture + personal stakes)
- One-paragraph = setup + **three disasters + ending**
- Disasters 2–3 preferably caused by protagonist trying to “fix things”
- Characters get motivation / goal / conflict / epiphany — not plot puppets
- Scene list before draft; kill conflict-free scenes
- Design documents stay editable mid-draft

## Normal

**Ten steps (summary)**

1. **One-sentence summary** (~1 hr) — NYT blurb practice; sell tool forever
2. **One-paragraph summary** (~1 hr) — ~five sentences; maps three-act: disaster1 ≈ end Act1; disaster2 ≈ midpoint; disaster3 ≈ end Act2 → Act3 wraps
3. **Character one-pagers** — per major: name; one-sentence storyline; abstract motivation; concrete goal; conflict; epiphany; one-paragraph storyline
4. **Expand paragraph → one-page synopsis** — each sentence → paragraph; all but last end in disaster
5. **Character synopses** — story from each major’s POV (½–1 page); editors often prefer these over plot synopsis
6. **Four-page synopsis** — expand each paragraph of (4); strategic logic
7. **Full character charts** — everything; how they change by end; cycle back to 1–6
8. **Scene spreadsheet** — one row/scene: POV what happens optional page estimate later chapter #; reorder freely (~100 scenes common)
9. **Optional narrative expansion** — multi-paragraph per scene; cool dialogue; he often skips now
10. **First draft** — solve small-scale logic with large-scale structure already working; mid-draft, refresh design docs

**Do / don’t**
- Do: cycle back to earlier steps whenever characters reveal holes
- Do: keep momentum — each step only needs to unlock the next
- Don’t: treat step 9 as mandatory
- Don’t: freeze step-1 sentence if step-3 proves it wrong

| Failure | Fix |
|---------|-----|
| Beautiful outline, dead desire to write | Shorten design cycle; draft sooner |
| Pantser pile with no spine | Elevator sentence → disasters → scene list for rewrite order |
| Scene list with no conflict rows | Scrub or add conflict before drafting |
| Design ignored mid-draft | Midpoint refresh of steps 1–8 |

## Hard

**Midstream uses (same method, different entry)**
- Hopeless draft → restart at step 1 (one-sentence clarity test)
- Finished pantser MS needing rewrite order → step 1 then later steps as revision plan
- Devastating edit letter / impossible deadline → week of Snowflake to clarify what to change

**Design philosophy edges**
- Design before *or* after drafting; he argues **before** is faster and yields better result — after still valid for salvage
- “Composting” (informal research/daydream/voices/theme) precedes step 1; Snowflake organizes compost, doesn’t replace it
- Proposal path: published novelists may sell from design docs; unpublished usually need full MS first (market reality, not craft purity)
- Step 8 spreadsheet as analysis tool: new versions as story develops; chapter column assigned late
- Mid-draft laugh-at-old-docs is success signal — documents are living, not sacred

**When to break / skip**
- Skip step 9 if scene spreadsheet + character charts already unlock draft speed
- Compress steps if short novel / novella — keep sentence → disasters → character GMC → scene list minimum
- Pure discovery writers: run Snowflake *after* zero draft as diagnostic, not as permission to start
