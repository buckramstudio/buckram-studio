# Builder: Mystery clue ledger

Spreadsheet-style clue / red-herring checklist for fair-play puzzles.

## Light

Job: one row per clue or herring; sort by plant chapter so the solution never uses off-page facts.

Contract: every reveal clue appears on-page *before* the solution uses it (fair-play).

Must-not-break:
- True solution recorded (author only)
- Every solution clue has Plant ch ≤ reveal ch
- No “detective suddenly knew” off-page facts
- ≥1 herring that felt fair
- Killer’s lie has a crack visible in retrospect
- Timeline of crime reconstructed without contradiction

## Normal

1. Case header
2. Suspect board
3. Clue / herring ledger + fair-play audit
4. Knowledge split (optional)
5. Plant → payoff timeline
6. Solution scene checklist

## Hard

**Howdunit / locked-room overlay**
- Add rows for physical constraints (access, alibi clock, impossible crime mechanism)
- Cross-link — mechanism clue type still needs Plant ch

**Thriller-secret variant**
- Central question may be “what will they do / who knows” — still ledger plants; fair-play bar optional but reader trust still needs planted capability

**Advanced diagnostics**

| Symptom | Cause | Fix |
|---------|-------|-----|
| Reader beats sleuth unfairly early | Too many C rows early | Delay true meaning; add RH |
| Reader never had a chance | Solution relies on F without flip | Convert to C with plant |
| MacGuffin eats mystery | M rows without true C spine | Cap M; restore crime question |

**Dramatic irony control:** Reader>Sleuth for suspense; Sleuth>Reader for procedural competence — pick per beat in knowledge split.
